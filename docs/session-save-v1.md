## 一、通关时长

### 总时长

**一次完整通关约 5-7 小时**，分布如下：

| 阶段 | 游戏内时间 | 现实时间 | 主要耗时点 |
|------|-----------|---------|-----------|
| Phase 1（扫描期） | 第1-2周 | 1.5-2小时 | 免费30人扫描 + 记录脉冲 + 初步观察 |
| Phase 2（收网期） | 第3-6周 | 2-2.5小时 | 集中观察 + 对质试探 + 发起对质 + C位维护 |
| Phase 3（终局期） | 第7-8周 | 1-1.5小时 | 半记忆觉醒 + 终局战 + 最终投票 |
| **合计** | **8周** | **5-7小时** | |

### 单次游玩时长（一次坐下玩多久）

游戏按"天"为最小叙事单位推进。每一天的内容量不同：

| 天的类型 | 现实时间 | 说明 |
|----------|---------|------|
| 普通日 | 3-8分钟 | 1-2段行为描写 + 简单选择（买股/观察/对话） |
| 策略对战日 | 10-15分钟 | 完整对战流程 + 三轴变化 + 多角色观察机会 |
| 塌房信号日 | 8-12分钟 | 触发事件 + 判断是否对质 + 情绪消化 |
| 对质日 | 15-25分钟 | 独占叙事 + 不可逆确认 + 后续反应 |
| 社区投票日 | 5-10分钟 | 投票 + 结果公示 + 排名变化 |
| 终局战日 | 20-30分钟 | 多轮战斗 + C位存活验证 + 最终投票 |

**建议单次游玩**：30-60分钟（约5-10个游戏日），适合碎片化游玩。

### 可跳过/加速的内容

- **已观察过的角色再次观察**：如果行为描写无变化，系统提示"上次观察后无新变化"，不重复收费
- **策略对战加速模式**：可选择"只看结果"跳过战斗过程，但会失去对战中的三轴观察机会
- **已读文本快进**：长按跳过已阅读过的文本段落

### 周目数

| 周目 | 目标 | 预估时长 |
|------|------|---------|
| 第1周目 | 盲玩，大概率银色或黑色结局 | 5-7小时 |
| 第2周目 | 带着上局记忆重玩，追求金色 | 4-5小时（跳过已读文本） |
| 第3周目+ | 换孽缘/C位组合，体验新路线 | 4-5小时 |

30种孽缘×C位组合 + 4种结局 = 理论上有充分的重玩价值。

## 二、存档系统

### 设计原则

1. **不可存档刷对质结果**——对质是核心不可逆决策，不能靠反复读档试错
2. **可以随时中断**——文字游戏玩家需要随时停下来
3. **存档本身是叙事元素**——不是冷冰冰的菜单，而是符合世界观的"日记本"

### 存档形式：站姐日记本

存档界面以**日记本**形式呈现。每次存档 = 写一篇日记。

```
📄 8月15日 · 阴
今天是第二周第三天。
观察了Milo的完整行为描写，脉冲触发medium。
他的谢幕习惯和记忆碎片里那个手势对不上……
但我不确定是我记错了还是他不是那个人。
应援值余额：3,240
嫌疑人名单：6人
C位候选：3人
对质机会剩余：3/3
```

### 存档类型

#### 1. 自动存档（系统日记）

- **触发时机**：每个游戏日结束时自动写入
- **数量**：仅保留最近1个自动存档
- **覆盖机制**：新一天开始时覆盖前一天
- **用途**：防止意外退出/崩溃丢失进度
- **限制**：不能在对质结果出来后回退到对质前

#### 2. 手动存档（日记条目）

- **触发时机**：玩家在非独占叙事时段主动存档
- **数量**：5个手动存档槽
- **可覆盖**：玩家可自由覆盖
- **限制**：
  - 对质独占叙事进行中不可存档（进入对质=锁定存档）
  - 终局战最终投票进行中不可存档
  - 存档时记录当前所有游戏状态（见下文"存档内容"）

#### 3. 关键节点存档（章节书签）

游戏在以下节点自动创建不可覆盖的"章节书签"：

| 书签节点 | 时机 | 说明 |
|----------|------|------|
| 开局 | 角色生成完成后 | 记录你的孽缘和C位（但玩家不可见） |
| Phase 1结束 | 第2周结束 | 你的嫌疑人名单初稿 |
| Phase 2结束 | 第6周结束 | 对质结果（无论成败） |
| 结局 | 最终投票后 | 你的结局 |

章节书签不能读取（不是存档点），但可以在通关后查看——"回看你的整本日记"。

### 存档内容

每个存档记录以下数据：

```

  save_id: "manual_3",
  timestamp: "2026-08-23T14:30:00",
  playtime_minutes: 187,
  in_game_date: "Week3_Day4",

  // 玩家状态
  support_points: 3240,
  cognition_dissonance: 18,

  // 主线状态

  suspect_list: ["Milo","Kai","Ash","Blair","Penn"],

    "Kai":  { confidence: 62, clues: [...], reactions: [...] },
    ...
  },
  confrontation_history: [],    // 对质记录

  // 条件线状态

### 防存档刷机制

核心设计：**对质是锁，存档是钥匙，但钥匙在对质前就收走了。**

| 场景 | 机制 |
|------|------|
| 玩家想在对质前存档，对质后读档重来 | **允许存档**，但对质结果一旦确定即写入自动存档+覆盖所有手动存档——你无法回到对质前 |
| 玩家想通过反复读档尝试不同的C位 | **最终投票后**，所有存档被锁定为"已通关"状态，不可回退 |
| 玩家想通过多存档槽同时尝试不同路线 | **5个手动存档槽**可以在不同时间点分叉，但对质和投票一旦发生，该存档的该状态不可逆 |

具体实现：
1. **对质开始**：进入独占叙事，存档功能锁定（UI灰显"正在记录……不可中断"）
2. **对质结果确定**：系统写入一条不可逆记录到存档中，同时更新所有5个手动存档的`confrontation_history`字段
3. **对质结束**：存档功能恢复，但所有存档已包含本次对质结果
4. **最终投票**：同理，投票后所有存档标记为`game_completed: true`，只能查看结局不能回退

### 文本流中的存档提示

当玩家尝试退出或关闭页面时：

```
┌─────────────────────────────────────┐
│            要离开了吗？               │
│                                     │
│  今天的日记还没写。                   │

│                                     │
│  [写完今天的日记再走]  [直接离开]      │

选"写完日记"=手动存档 + 退出。选"直接离开"=自动存档 + 退出。

## 四、技术实现备注

### 存储方式

- **本地存储**：使用浏览器 localStorage / IndexedDB（如果是网页版）
- **存档大小预估**：单个存档约 50-100KB（主要是已读文本ID列表占用）
- **总存储需求**：5个手动 + 1个自动 + 章节书签 ≈ 1MB以内

### 云存档（可选，v2功能）

- 如果接入账号系统，可支持云同步
- 对质防刷机制在服务端校验（即使本地存档被篡改，对质结果仍以服务端记录为准）

### 防作弊

- 存档中的`nemesis_id`和`c_position_id`在游戏过程中对玩家不可见
- 即使玩家通过开发者工具查看存档JSON发现这两个字段，也只能知道"这一局谁是我的孽缘/C位"——但游戏体验建立在"你已经知道了但要在游戏中验证"的前提下，所以这不构成严重剧透
- 真正需要防的是对质结果篡改——`confrontation_history`和`game_completed`字段一旦写入，前端UI不允许回退

---

> **一句话总结**：5-7小时通关，随时可存（日记本形式），但对质和投票一旦发生不可逆转——你的日记写了就不能撕掉。
